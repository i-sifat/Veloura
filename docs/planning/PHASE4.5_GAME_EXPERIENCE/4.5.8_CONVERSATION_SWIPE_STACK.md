### Swipe interaction
- Horizontal drag: the card follows `dx`, rotates `dx / 24` degrees, and begins fading past 96px.
- Release past 96px **or** with velocity above 700 -> throw out over 320ms (easeOutCubic) to
  `dx.sign * 1.4 * screenWidth`. Otherwise spring back over 220ms. This matches the velocity-aware
  behaviour already established for the Truth or Dare deck in Phase 3.1 — reuse that gesture logic if
  it is extractable rather than writing a second implementation.
- `lightImpact` on a committed swipe. The next card promotes with a 220ms scale + offset tween.
- **Both directions do the same thing** (next question). Do not build like / dislike semantics — there
  would be nothing to teach the user and nothing to do with the signal.
- Every committed swipe or CTA tap calls `nextTurn()` so partners alternate answering, and writes the
  existing "answered together" timestamp.
