# 4.5.0 — Game Design System (reference, no code of its own)

Implemented in **`lib/theme/game_tokens.dart`** as `GameTokens` (all `static const`) during 4.5.1.
Every later sub-phase reads from it. No widget re-declares these values inline.

Base grid 4pt. Reference viewport **390 x 844**. Also verify **360 x 800** and **430 x 932**.

---

## 1. Relationship to the existing theme (important)

The app already has a locked palette in `lib/theme/app_colors.dart` from Phase 1:
`background #120B16`, `surface #1D1423`, `card #2A1D31`, `primary #FF4D6D`, `secondary #FF8FA3`,
`accent #FFB703`, `success #54D67A`, `textPrimary #FFFFFF`, `textSecondary #B9B3C5`, `divider #392A42`.

**`GameTokens` extends that palette. It does not replace it and it introduces no second brand colour.**

- The primary action colour stays `AppColors.primary #FF4D6D`. `GameTokens.rose` is an alias of it.
- Premium accents use `AppColors.accent #FFB703`. Do not introduce a separate gold.
- Sheets and cards use `AppColors.surface` / `AppColors.card`.
- What is genuinely new is a **games-only plum backdrop gradient** and the deck/wheel accent sets
  below. Those exist only inside game screens.

```
// games-only backdrop stops (start from the app background, travel toward plum)
bgTop     #120B16   (= AppColors.background)
bgMid     #2B0B36
bgBottom  #47124F
vignette  #0B0210

// derived accents
rose      #FF4D6D   (= AppColors.primary)
roseLight #FF8FA3   (= AppColors.secondary)
roseDeep  #C81E67

// surfaces
glass       #FFFFFF @ 6%
glassStrong #FFFFFF @ 10%
hairline    #FFFFFF @ 12%
sheet       #1D1423  (= AppColors.surface, 96% opaque)
scrim       #08010C @ 60%
textOnLight #2A0A2E   // text printed on dice faces / light cards
```

### Backdrop recipe (`GameBackdrop`)
```
Stack, bottom -> top:
1. LinearGradient(topLeft -> bottomRight, [bgTop, bgMid, bgBottom], stops [0.0, 0.55, 1.0])
2. RadialGradient(center Alignment(0, -0.35), radius 0.95, [#5B1668 @ 55%, transparent])
3. RadialGradient(center center, radius 1.05, [transparent, vignette])
```

## 4. Motion

| Token | Duration | Curve |
|---|---|---|
| `tapScale` | 110ms | easeOut (1.0 -> 0.97) |
| `fade` | 220ms | easeOut |
| `sheetIn` | 320ms | easeOutCubic |
| `cardFan` | 420ms | easeOutCubic, 60ms stagger |
| `cardFlip` | 620ms | easeInOutCubic |
| `wheelSpin` | 4200ms | `Cubic(0.12, 0.78, 0.06, 1.0)` |
| `pulseGlow` | 900ms | easeInOut, repeat reverse |
| `breathe` | 3200ms | easeInOut, repeat reverse |

Perspective for all 3D transforms: `Matrix4.identity()..setEntry(3, 2, 0.0012)`.
Dice tumble timings are **not** listed here — they belong to Phase 3.5 and must not be re-specified.

The master plan's motion quality bar (§3) applies: non-uniform speed, deterministic end state,
reduced-motion path, never inside a `BackdropFilter`, profiled on a low-end physical device.

## 5. Haptics

```
tile tap / CTA press     lightImpact
card flip completes      mediumImpact
wheel segment tick       selectionClick (throttle: min 45ms apart)
reveal / landing         heavyImpact
tempo beat               lightImpact (max 2 per second)
```
All of it routes through one helper that respects the haptics setting built in Phase 7. Dice haptics
stay owned by Phase 3.5; this phase only resolves its `TODO(phase7)` call site if it is still open.

Register the folders in `pubspec.yaml`. **Every `Image.asset` supplies an `errorBuilder` falling back
to `GameTileGlyph`** — a missing asset never breaks a build or renders a grey box. Artwork is a design
task outside codegen; the fallback is what makes these sub-phases shippable before art lands.
