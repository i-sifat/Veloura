## 0. Rules (apply to this whole sub-phase)

1. Implement only what this file lists. One sub-phase = one branch = one PR (`phase/4.5.1-game-shell`).
2. Nothing existing is deleted unless this file says so. Engines, controllers and packs are untouched.
3. Architecture per `ARCHITECTURE.md`: Riverpod + codegen only; `xxxRepositoryProvider` /
   `xxxControllerProvider` / `xxxStateProvider`; `presentation -> domain <- data`; UI never touches
   Hive; repositories return `AppResult` and never throw past their boundary; one `provider.dart`
   barrel per feature.
4. No new dependencies.
5. No magic numbers — every value comes from `GameTokens` or `AppColors`. Missing values get added to
   `GameTokens` and called out in the PR.
6. Claim Hive typeIds in `docs/planning/HIVE_TYPEIDS.md` **before** writing adapters. IDs 0 and 1 are
   taken; 2 is the next free.
7. Randomness is injected via a `randomProvider` so tests can seed it. Never `Random()` in `build()`.
8. Wrap animated heroes in `RepaintBoundary`. No `BackdropFilter` over an animating subtree.
9. Honour `MediaQuery.disableAnimations`: long animations collapse to a 220ms fade. Tap targets 44x44.
   Semantics labels on every icon-only button.
10. Cognitive-load contract from the folder README is part of the exit gate.
11. Definition of Done: `flutter analyze` zero issues, `dart run build_runner build
    --delete-conflicting-outputs` clean, `flutter test` green, screenshots at 390x844 and 360x800 in
    the PR. Commit style `feat(games): ...`.

## 1. Goal

Three things ship together because every later sub-phase needs all three, plus the new hub:

1. `GameTokens` — the design system in code.
2. `GameShell` + shared game widgets — the frame every game screen sits in.
3. `GameSession` — two named players and whose turn it is, persisted and shared by all games.
   **This is the fix for "the app only shows one player": there was never a session model.**
4. The Games tab becomes a 2-column gradient grid of six games.

## 3. Session model

```dart
// lib/features/session/domain/player.dart          Hive typeId 2
class Player {
  final String id;        // uuid v4
  final String name;      // max 12 chars
  final int colorValue;   // ARGB
}

// lib/features/session/domain/game_session.dart    Hive typeId 3
class GameSession {
  final Player a;
  final Player b;
  final int activeIndex;  // 0 => a's turn
  final DateTime startedAt;

  Player get active  => activeIndex == 0 ? a : b;
  Player get passive => activeIndex == 0 ? b : a;
  GameSession advanced() => copyWith(activeIndex: 1 - activeIndex);
}
```
Use `freezed` for both (D-4) and generate Hive adapters separately (D-1).

- `sessionRepositoryProvider` -> `SessionRepositoryHive`, box `session_box`, single key `current`,
  returns `AppResult<GameSession?>` / `AppResult<void>`.
- `sessionControllerProvider` -> `AsyncNotifier<GameSession>`: `load()`, `setPlayers(a, b)`,
  `nextTurn()`, `resetTurns()`.
- `gameSessionStateProvider` -> read-only projection for widgets.
- Defaults when the box is empty: `Player("You", #FF4D6D)` and `Player("Partner", #8E4BD1)`.
- **Turn contract: a game calls `nextTurn()` exactly once, when the player confirms the result
  ("Done"). Never on the roll, spin, draw or swipe itself.** Every later sub-phase depends on this.

## 6. `GamePreferencesSheet`

The only home for switches. Rows 56 tall, label `bodyMid`, `Switch.adaptive` with `activeColor: rose`.
```
Third die (intensity / duration)      default OFF   (reads the existing dice preference)
Vibration                             default ON    (Phase 7 owns the master setting)
Sound                                 default OFF   (audio lands in Phase 9)
Soften decks (hide Superhot)          default OFF
Custom dice faces      -> premium row with PremiumLockBadge, pushes the paywall
Who's playing?         -> WhoIsPlayingSheet
```
Persist through `shared_preferences` (no new Hive typeIds). Where a preference already exists in the
dice module, read and write that one — do not create a second source of truth.
